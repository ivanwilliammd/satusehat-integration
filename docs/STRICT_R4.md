# Strict R4 mode

Builders can write elements that do not exist on their resource. The payload is still valid JSON and
structural validation stays quiet — but FHIR R4 does not know the element, and SATUSEHAT will reject
or ignore it.

## Enabling

```bash
export SATUSEHAT_STRICT_R4=1
```

`Builder::build()` then calls `R4ElementGuard::assert()` and throws `InvalidArgumentException` naming
the resource and the offending elements:

```
Goal writes an element that does not exist in FHIR R4: startDateTime
```

## Why opt-in instead of default

Turning it on by default would break callers that still use the generic setters. The mistake is real,
but cutting off production callers is not this library's call — the owner of that code decides when to
move.

## Basis of the check

`data/r4_elements.json` — 148 resources, generated by `scripts/generate_r4_elements.py` from the
official HL7 R4 `profiles-resources.json`. Choice elements (`onset[x]`, `deceased[x]`) are expanded to
their concrete names, so valid shapes are not reported as violations.

Resources that do not exist in R4 (e.g. `ChargeItemResponse`) are not checked: there is no basis to
call them wrong. The seven such builders are already marked `@deprecated` in
`docs/R4_CONFLICT_TRIAGE.md`.
